# Park UI source provenance

Core controls are based on [Park UI](https://github.com/chakra-ui/park-ui), revision `102769cc91a9d36753dbc5893c74b7954b495efe`, retrieved 2026-10-27. Upstream license is preserved in [LICENSE.park-ui](LICENSE.park-ui).

Input, Text and Heading retain the upstream styled-component structure from `components/react/src/components/ui/`, with local generated-runtime imports. Button and IconButton adapt the same directory's native/Ark composition. The button and input recipes are no longer adapted from Park: they are the existing app's own control contract (`frontend/src/ui-system.css` and `interaction-system.css`) written as Panda recipes, and the theme they draw on is derived entirely from `@clipkit/design-tokens`; no Panda preset tokens are loaded. Typography recipes are local role definitions.

Intentional changes: ClipKit semantic colors; neutral default action; sm/md/lg sizes; explicit icon-only dimensions; required icon-button label; smaller loading API with native disabled and aria-busy; no ButtonGroup/Loader dependency yet. The foundation does not install Park's full preset, all palettes or unused widgets. It is an editable source integration, not a claim that `@park-ui/cli` is a runtime dependency.

When updating, compare these source paths against the recorded revision, preserve local contracts and rerun state/consumer checks. Do not overwrite components with an unreviewed CLI update.

Nunito is copied from the existing app, with its OFL license in `assets/OFL-Nunito.txt`. It is bundled locally and makes no network font request.

Milestone 2 adds Select, Popover and Dialog compound sources from the same pinned Park revision and directory. Their `createStyleContext` calls use Panda 2's `createSlotRecipeContext`; local slot recipes supply ClipKit surfaces and viewport constraints. Popover RootProvider uses Ark's corresponding RootProvider. Checkbox adapts the Park/Ark structure with a compact controlled API; ChoiceSelect, Paging, Tabs, MediaCard and Sidebar are local Ark compositions, and SearchField, Tag, StatusBadge, Notice, EmptyState, PageHeader, SectionHeading, Toolbar, FilterRail, Panel, Rule, Stat, Identity, Avatar and the other surfaces in `components/surfaces.tsx` are local native compositions. Viewer composes Ark's Dialog with the existing app's viewer chrome, and its Organizer parts are native. CoverMosaic, Hero, FolderCard and FolderTree are local native compositions of the existing app's collection rules, and SourceCard and RemoteItem of its Following rules; SettingsNav, SettingsCard and Storage of its Settings rules; ReviewNav, Comparison and DecisionBar of its duplicate review rules. The select, popover, dialog, tabs and search-field recipes are the existing app's rules, not Park's. All retain Ark behavior rather than implementing overlay positioning or keyboard state machines in the app.
